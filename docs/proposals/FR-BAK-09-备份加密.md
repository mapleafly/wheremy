# 新增功能提案：FR-BAK-09 备份加密

> 按 `templates/feature-proposal.md` 填；入口条件与步骤见 `PROCESS.md` §3.1。
> **本提案不直接开工**——它把"问题、备选、代价、建议、以及最难的'忘了口令怎么办'"摆清楚，等用户拍板。

## 0. 基本信息

| 项 | 内容 |
|---|---|
| 提案人 / 日期 | 开发（2026-10-13） |
| FR id | `FR-BAK-09`（已有条目，状态 `⬜`；见 `PRD.md` §3.8 与 §5 一览） |
| 一句话标题 + 状态 | 「导出的备份包可以加密，免得放进网盘就等于公开」——`⬜ 待用户拍板` |

## 1. 一句话价值

用户可以把备份包放进网盘/共享目录/发给未来的自己，而**不用先担心"这包里有我家东西的照片和位置"**。

## 2. 用户场景

- 前置：机器里有若干物品与照片，**自动导出已开**（`FR-BAK-08`：每天一份，落在用户选的目录）。
- 步骤：1) 换手机 / 想留一份到网盘 → 2) 导出时勾"加密"并设一个口令 → 3) 把包上传 → 4) 新机上导入时它问口令 → 5) 输对就还原。
- 现状哪里不够用：**包是明文 zip**。包里到底有什么（已核过，见 `RELEASE.md` §9 第 25 条）：

  | 内容 | 泄露的后果 |
  |---|---|
  | `photos/originals/<照片>.jpg` | **家里东西的照片**（含可能带地址信息的画面） |
  | `data.json` | 物品名、类别、颜色、品牌、**位置树**、备注、到期日——等于一份"家里有什么、放在哪、值不值钱"的清单 |
  | `manifest.json` | 版本号与导出时间（本身不敏感） |

  ⚠️ **最现实的风险不是"你主动上传"，而是自动导出 + 云同步**：`FR-BAK-08` 每天往你选的目录写一份包；
  只要那个目录落在"相册自动备份/网盘同步"的范围内，**你从没点过上传，包也会自己上去**（而且是每天一份）。
  触发条件（`PRD.md` 原文）是"用户把 zip 放进网盘/共享目录"——这条在自动导出打开之后**很容易在你不知情时成立**。

## 3. 成功判据（可测）

| # | 判据 | 怎么测（命令 / 界面动作） |
|---|---|---|
| 1 | 加密包**在文件层面看不出内容**：`data.json` 与照片条目都不是明文，也读不出物品名/位置 | 命令：对包跑 `strings`/解压后肉眼查（不贴内容进文档），断言关键字符串一个都搜不到 |
| 2 | 口令正确时**逐字节还原**：导入后的 `data.json` 与照片哈希与导出前一致 | 单测：导出 → 导入 → 比对哈希（同 `RELEASE.md` §10.8 的做法） |
| 3 | 口令错误时**立刻报"口令不对"且一行都不写库** | 单测：错口令导入 → 断言库未变 + 错误类型是"口令不对"（不是"文件坏了"） |
| 4 | 密文被改一个字节时**整体拒绝**（认证失败），不产生半截数据 | 单测：翻一个密文字节 → 断言拒绝 + 库未变 |
| 5 | **旧包（明文 v1）仍能导入**，不因新增 v2 而失效 | 单测：喂一个 v1 包 → 正常导入（`FR-BAK-07` 的兼容承诺） |
| 6 | 自动导出**不会因为加密而每天问你口令**（本机记住），但包里**不含任何口令/密钥** | 单测 + 真机：跑一次自动导出看是否询问；检查包内条目名（`FR-BAK-04` 不可放松） |
| 7 | 忘了口令时，界面与文档说的**是同一句话**，且不撒谎（不承诺可恢复） | 真机 + 逐字文案比对（`RULES.md` 的 🗣） |

## 4. 与现有 FR 的关系

- 关系：**新增**（在 `FR-BAK-01` 手动导出 / `FR-BAK-02` 两种导入模式之上加一层可选加密）。
- 不变量不能破：**`FR-BAK-04`「包里不含 API key、不含任何设置」**（安全条款，不可放松）——加密后更要守住：**口令不写进包**。
- `FR-BAK-07`「格式与 Room schema 解耦」继续成立：加密只动**容器**，`data.json` 的内容与版本规则不变。
- 兼容规则要补一条（与 `RELEASE.md` §5.2 同构）：**旧版本应用读到 `formatVersion = 2` 必须拒收并说清"这个包更新，请升级应用"**。
- `PRD.md` §7 测试索引：给 `FR-BAK-09` 加一行 → `BackupEncryptionTest`。

## 5. 触发条件与代价（必填）

| 项 | 内容 |
|---|---|
| 触发条件 | 用户把 zip 放进网盘/共享目录（`PRD.md` 原文）；**自动导出开启后，这条随时可能被动成立** |
| 代价 | **中**：格式升到 v2 + 口令派生与加密流 + 两个对话框（导出设口令 / 导入输口令）+ 保持 v1 可读 + 测试与文档 + **重跑一遍迁移/反面演练**（含加密包） |
| 现在为什么不做 | 目前包只留在本机/自己的电脑上（触发条件没成立）；且要先把"忘了口令"这句话定死才敢做 |

**设计草案（决定做的话按这个走）**：

| 项 | 选择 | 理由 |
|---|---|---|
| 加密算法 | **AES-256-GCM**（`javax.crypto` 自带，无需新依赖） | 带认证标签 → 判据 4 能成立；免去"自己拼 HMAC" |
| 口令派生 | **PBKDF2-HMAC-SHA256**，随机 16 字节 salt，迭代次数写在包里（起步 210k） | 同样是 JDK 自带；迭代数可随年份上调且旧包仍可读 |
| 包结构 | 明文小头 `manifest.json`（`formatVersion = 2` + `encryption: {alg, kdf, iterations, salt}` + **校验块 verifier**）+ 加密的 `data.enc` 与 `photos/**.enc`（每条目随机 IV） | 导入时必须**先知道"这包要不要口令"**才能问；校验块让错口令**立刻**失败（判据 3） |
| 口令存放 | **只在本机**（与 API key 同款：本地加密存储），用于自动导出；**换机/导入时手输** | 自动导出才不会每天问你；且不违反 `FR-BAK-04` |
| 忘了口令 | 见下 §5.2（**这是本提案的核心**） | 必须写死，不留模糊 |

## 5.1 备选项与建议

| 选项 | 做什么 | 代价 | 什么时候选 |
|---|---|---|---|
| **A（不做 + 提示与文档）** | 导出后提示"这是**明文**包，放进网盘前请先加密"，并在文档里给"网盘保险箱 / 7z / VeraCrypt"的做法 | 小（文案 + 文档） | 包只留在本机、或你愿意每次手动加密 |
| **B（做全包加密，自选口令）** | 上面那套设计草案；`formatVersion` 升 2；明文 v1 仍可读 | 中 | **建议**：只要包可能离开本机 |
| **C（B 的变体：随机强口令）** | 导出时生成一个强口令，显示一次让你抄进密码管理器（而不是你自己想一个） | 与 B 相同 | 担心自己设的口令太弱——**我更推荐这个** |
| **D（只加密照片，不加密 JSON）** | —— | —— | ❌ **不推荐**：位置树/物品名才是"最值钱"的信息，等于没加密 |
| **E（用设备密钥加密）** | 用本机 Keystore 里的密钥加解密 | 小 | ❌ **不推荐**：换机就解不开，**直接违背备份的目的** |

**我的建议：做 B（口令用 C 的方式生成，允许你改成自己的）**。理由是那条"自动导出 + 云同步"的现实路径——
一个每天自动产生的、含照片与位置清单的明文包，靠"记得手动加密"来防，迟早会漏一次；
而这件事的代价是"中"，且**不动 Room schema**（只动备份格式），做一次就永久解决了。

**如果暂时不做**：至少做 A（一句提示 + 文档），把风险显式说出来，别让"包是明文"这件事只写在 PRD 里。

## 5.2 忘了口令怎么办（**必须先定死这一句，否则不许开工**）

这是 `PRD.md` 里"必须能处理'忘了口令'这句话"的具体化。我的建议是这五条：

1. **没有后门，也没有恢复密钥**：口令不存进包、我们不留副本，**忘了就是打不开**——这句话要**逐字**出现在
   设口令的对话框与文档里（`RULES.md` 的 🗣），不许含糊成"请妥善保管"。
2. **但损失有界**：原库还在手机上，随时能重新导一份明文包。**只有"手机也没了 + 口令也忘了"才是真的丢**——
   这句也要写进同一处提示（它是让用户不恐慌、也敢用加密的关键）。
3. **导入先验口令**（校验块 / GCM 认证标签）：错口令立刻说"**口令不对**"，而不是写坏库或报"文件损坏"（判据 3）。
4. **口令只在这台手机上记住**（本地加密存储）：自动导出不问口令；**换机/新机导入必须手输**——
   所以文档要提醒"口令抄进密码管理器，别只记在脑子里"。
5. **不做"找回"**：不做恢复码、不做提示问题（成本高、体验差，而且会制造"其实还能找回"的错觉）。

> 若用户接受这五条 → 做 B/C；若不接受（比如希望"忘了也能救"）→ **就别做加密**（选 A），
> 因为"能救回来"与"真的加密了"在密码学上不能同时成立。
